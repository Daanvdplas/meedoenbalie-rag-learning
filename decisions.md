# Decisions for the two-document experiment

Scope: two fictional activity documents, five fixed gardening questions and free queries, Rust retrieval and human review. No database, resident accounts, automatic eligibility decisions or larger benchmark.

- Keep the quantized multilingual MiniLM model and fastembed 7.1.2 chosen for the first slice. Query and document embeddings share one model instance. No prefixes; section inputs are document title, newline, heading, newline and exact section text. Maximum input length is explicitly 512 tokens; 384 dimensions are validated. No tuning to the five expected answers.
- Read document ID and source date from the source itself. Reject missing/duplicate metadata, invalid calendar dates, duplicate/empty section IDs, empty headings or empty evidence. Every section retains its document ID/title/date; repeated section IDs across documents are namespaced as document-ID:section-ID in citations and evaluation. IDs and exact text in results come from those parsed sections. Duplicate document IDs are rejected.
- Keep document vectors in memory, built once at process start. No persistent vector index can become incompatible. The manifest records per-document IDs/dates/hashes, the corpus hash, exact embedding-input hash and vector hash, model, dimensions, SDK, encoding/chunk/filter settings, platform and fixed `as_of`. Model downloads use the provider's mutable repository revision; the vector hash detects changed document embeddings, but this does not promise bit-identical output across platforms or future model downloads. Keep the cache for local replay.
- Gardening source date is **2026-10-20**; bicycle-workshop source date is **2026-10-18**. The availability observation in the text is **2026-09-01**. The reference date is **2026-10-20**. These are distinct: source freshness never establishes current places. Transport is absent from the source, so its status remains unknown. Retrieval does not infer these facts or generate an answer.
- Default top-k is 3, configurable from 1 through 6. Ties use document ID followed by section ID; top-k remains bounded at 6 across twelve indexed sections. Dense scores are cosine similarity; the baseline uses Jaccard overlap of lowercase alphanumeric tokens over the same title/heading/text input, without tuned stopwords. Neither method has a no-match threshold.
- Five-question evaluation is a transparent learning record, not a held-out benchmark or quality gate. It counts distinct required source sections, keeps unknown criteria separate and assesses no generated claims. All five prepared questions explicitly name gardening and retain only gardening gold labels; free questions search both documents and are unscored. Gold is read by the CLI evaluator and explicit human-review endpoint, never indexed or returned by search.
- Deterministic CI checks run formatting, clippy, tests and build without loading/downloading an embedding model. Dependency/native runtime downloads may still occur during compilation. The live five-question evaluation is a separate local command.

Sources: [fastembed 7.1.2](https://github.com/anush008/fastembed-rs/releases/tag/v7.1.2), published **19 October 2026**; [checkout 7.0.1](https://github.com/actions/checkout/releases/tag/v7.0.1), published **20 July 2026**. CI pins the checkout action commit.

The title-context change addresses lost activity context in isolated schedule/location sections. A recorded three-query ablation uses the same two documents and unchanged model. It improves some similarities but does not make the exact gardening where/when question complete in the first three hits: location remains fifth. No hand-coded ranking, no threshold calibration and no perfect retrieval claim.
