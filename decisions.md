# Decisions for the five-activity experiment

Scope: five fictional activity documents, free queries and five internal fixed gardening regression questions, Rust retrieval and inspectable answers. No database, resident accounts, automatic eligibility decisions or larger benchmark.

- Keep the quantized multilingual MiniLM model and fastembed 7.1.2 chosen for the first slice. Query and document embeddings share one model instance. No prefixes; section inputs are document title, newline, heading, newline and exact section text. Maximum input length is explicitly 512 tokens; 384 dimensions are validated. No tuning to the five expected answers.
- Read document ID and source date from the source itself. Reject missing/duplicate metadata, invalid calendar dates, duplicate/empty section IDs, empty headings or empty evidence. Every section retains its document ID/title/date; repeated section IDs across documents are namespaced as document-ID:section-ID in citations and evaluation. IDs and exact text in results come from those parsed sections. Duplicate document IDs and corpora larger than five documents are rejected.
- Keep document vectors in memory, built once at process start. No persistent vector index can become incompatible. The manifest records per-document IDs/dates/hashes, the corpus hash, exact embedding-input hash and vector hash, model, dimensions, SDK, encoding/chunk/filter settings, platform and fixed `as_of`. Model downloads use the provider's mutable repository revision; the vector hash detects changed document embeddings, but this does not promise bit-identical output across platforms or future model downloads. Keep the cache for local replay.
- Gardening source date is **2026-10-20**; bicycle-workshop source date is **2026-10-18**. The gardening availability observation is **2026-09-01**; the bicycle-workshop observation is **2026-10-18**. Language-cafe, cooking and walking dates are **2026-10-19**, **2026-10-17** and **2026-10-20**; they record no current place counts. The reference date is **2026-10-20**. These are distinct: source freshness never establishes current places. Transport is absent from the gardening source and explicitly undocumented in the bicycle source, so its status remains unknown. Retrieval does not infer these facts or generate an answer.
- Default top-k is 3, configurable from 1 through 6. Ties use document ID followed by section ID; top-k remains bounded at 6 across thirty indexed sections. Dense scores are cosine similarity; the baseline uses Jaccard overlap of lowercase alphanumeric tokens over the same title/heading/text input, without tuned stopwords. Neither method has a no-match threshold.
- Five-question evaluation is a transparent learning record, not a held-out benchmark or quality gate. It counts distinct required source sections, keeps unknown criteria separate and assesses no generated claims. All five prepared questions explicitly name gardening and retain only gardening gold labels; free questions search all five documents and are unscored. The demo exposes no judgement/criteria controls. Gold remains readable only by the CLI evaluator and the existing gated internal human-review endpoint, never indexed or returned by search.
- Deterministic CI checks run formatting, clippy, tests and build without loading/downloading an embedding model. Dependency/native runtime downloads may still occur during compilation. The live five-question evaluation is a separate local command.

Sources: [fastembed 7.1.2](https://github.com/anush008/fastembed-rs/releases/tag/v7.1.2), published **19 October 2026**; [checkout 7.0.1](https://github.com/actions/checkout/releases/tag/v7.0.1), published **20 July 2026**. CI pins the checkout action commit.

Document titles are now short activity names. The historical two-document ablation remains a snapshot of its previous titles and corpus; it is not a claim about the new five-document ranking. The model and generic title/heading/text encoding remain unchanged. New live measurements retain misses rather than forcing expected ranking. Top-k and the four-search budget bound work; a broad response can remain incomplete.

The UI keeps one user question distinct from Codex's additional focused search actions. Exact quotes are highlighted in returned passages inside one collapsible search-details panel, with document/date and a source link. There is no separate evidence block or judgement flow. Activities are compact, independently expandable source documents above the question field.
