Who does what?

Browser → Rust app → Codex ↔ Rust search. Codex writes the answer; Rust checks the citations and returns it to the browser.

Browser
static/index.html
Sends a question, polls its run, displays the answer and actual retrieved passages.
Rust coordinator
src/web.rs
src/runs.rs
Tracks a bounded in-memory run history and starts the answer process. No database; history disappears on restart.
Answer writer
src/codex.rs
Uses the local Codex runtime to reach an external model. The only allowed tool is read-only search. Checks the output shape, citation identities, dates, and literal quotes; does not prove every prose claim.
Local retrieval
src/lib.rs
src/mcp.rs
Turns text into local MiniLM embeddings and ranks sections by similarity. Five fictional documents have thirty sections. Similarity is not answer confidence. The MCP search process loads its own in-memory index.
CLI and experiments
src/main.rs
src/experiment/
CLI search shares the Rust retrieval implementation. Experiments compare approaches and grade saved answers separately; live model runs require explicit opt-in.

Three questions to keep asking

What enters and leaves this part? Why did we choose it? What does its test establish, and what remains uncertain?

A document dated 20 October can contain availability last observed on 1 September. An exact citation preserves that observation; it cannot make the observation current.
