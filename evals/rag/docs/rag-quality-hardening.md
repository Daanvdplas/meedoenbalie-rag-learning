# RAG quality: evidence first, answers separately

Implementation tracking: [epic #84](https://github.com/Daanvdplas/meedoenbalie-rag-learning/issues/84).

## What the comparison means

The same five fictional activity documents remain the corpus. The existing eighteen
questions are **seen development/regression cases**, including the formerly named
held-out file. Four storage/structure profiles are parity comparisons, not four
independent statistical replications. SQLite currently loads data for the same Rust
scorer; it is not a separate native SQL vector/FTS ranking algorithm.

The primary retrieval result is **all labelled source-evidence goals found**:
count complete cases / cases with a nonempty source-evidence target. Report the
numerator and denominator. Average partial goal coverage is a different result,
shown separately. A higher partial average does not imply more completely
supported questions. For the old eighteen-case baseline, the expert audit found
dense 7/15 complete versus RRF 6/15, despite RRF's higher partial average.

Goals have OR alternatives, each containing AND source references. A goal can
support an explicit source statement that something is unknown; those nonempty
targets still count. An empty target is N/A, not a successful or failed retrieval
goal. P05, P12 and T06 stay visible with their unknown/no-match obligations and
answer assessment pending. No answer is generated by the local retrieval matrix.

`retrieval-task-metrics-v1` is a separately versioned derived report view. It is
recomputed from raw records and freshly computed protected expectations whenever
the report is built. It does not change stored JSONL, frozen labels, or
`retrieval-assessment-v2`. Existing v2 metrics retain their existing definitions.
Imported deterministic v2 assessments must exactly match recomputation and the
current criteria hash; otherwise explicitly reassess into a new file, without
repeating retrieval. Manual retrieval judgments remain separate. They are not
answer correctness labels.

## Required measurements

- Complete labelled source-evidence goal set, partial coverage and their explicit
  applicable counts; failed/invalid runs and targetless cases remain separate.
- First **goal-support** reciprocal rank: only the union of required source-goal
  references, excluding relevance-only exclusion evidence. Expansion is not a rank.
  This is distinct from the historical relevance MRR.
- Exact minimum distinct sections needed to satisfy all AND/OR goals. In fixed
  section mode, compare this lower bound to top-k. T05 requires four sections and
  cannot be complete with top-k three. In activity expansion mode, top-k counts
  seeds, so it is not an offered-section capacity bound. The token ceiling still
  applies; passing the section lower bound does not prove token feasibility.
- Technical checks and measured local search timings remain separate from quality.
  Count shared preparation once per batch. An estimated source token count is not
  total model input, provider usage, money, or latency.
- Actual answers, unknown/no-match handling and citation quality need separate
  answer evaluation. Their state remains pending/not generated. AI judging is
  paused, and no agent fills in a field presented as a human judgment.

The fresh set is a **question-level holdout on the same five documents**, not
unseen-document generalisation and not human-calibrated ground truth. Source
dates and corpus bytes remain frozen. Question inputs and explicit typed user
constraints stay separate from protected answer actions, references and labels.
Validate source identities, question/criteria hashes and canonical references
before measurement. Do not inspect its scores before independent review/freeze
or tune retrieval on its outcomes.

Predeclare baseline top-k 3 sections, top-k 3 with activity expansion, and top-k 6
sections, keeping candidate and context budgets fixed (context estimate 1200).
Use all eighteen old questions and then the independently frozen twelve. Main
baseline covers four methods × four profiles; context ablations are bounded
settings, not an unbounded factorial experiment. Typed filters may only express
explicit user conditions, with no hidden case-ID rules or gold leakage. Preserve
all old evidence and write each run/report to a new path.

Compact MCP work must preserve source IDs/dates and guards. Measure serialized
payload changes locally first. Any actual Codex comparison needs a new explicitly
authorized bounded ledger, separate from the exhausted old ledger; no free judge.
Do not infer latency, cost or answer-quality gains solely from fewer characters.

## Verification

Meaningful regression tests cover zero versus N/A, sourced uncertainty, goal-role
ranking versus exclusions, overlapping AND/OR alternatives, T05's capacity bound,
invalid evidence/trace, altered imported grades and immutable output files. Final
verification recomputes historical complete counts, validates new data before
measurement, reproduces the bounded matrices, and walks through the actual HTML
in a browser. All product changes use independently reviewed PRs into the
integration branch, then the final reviewed release.
